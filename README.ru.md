## Что такое DuoNet?

DuoNet — это экспериментальная **децентрализованная сеть связи**, объединяющая:

- **Сквозное шифрование** (E2EE) с пост-компромиссной безопасностью
- **Архитектуру слепого сервера** — сервер ретранслирует зашифрованные сообщения, никогда не видя открытый текст
- **Устав сообщества** — социальный контракт, определяющий ценности и ограничения сети
- **Встроенный прокси-сервис** — делитесь интернет-каналом и зарабатывайте доверие
- **Обнаружение пиров** через mDNS (локальная сеть) и Rendezvous-серверы (глобально)

В отличие от традиционных мессенджеров, у DuoNet **нет центральной власти**, **нет компании-владельца** и **нет единой точки контроля**. Технология объявлена **общественным достоянием** (Статья 1 Устава), то есть никто не может запатентовать, ограничить или монополизировать её.

## 🧠 Уникальные концепции

### 1. Устав сообщества DuoNet

Это **не юридический документ**, а **социальный контракт**, который участники добровольно принимают. Ключевые статьи:

- **Статья 1 (Общественное достояние)** — Технология принадлежит всему человечеству. Никаких патентов, никаких ограничений.
- **Статья 4.5 (Лимит сервера)** — Оператор сервера обязуется не обслуживать более **450 уникальных пользователей в сутки**. Это предотвращает централизацию.
- **Статья 6.1 (Нет модерации)** — В сети нет модерации, банов или механизмов контроля. Технология — это инструмент, а не судья.

Устав криптографически подписывается каждым аккаунтом при регистрации.

### 2. Архитектура слепого сервера

Сервер **никогда не видит открытый текст**. Все сообщения (включая системные, такие как запросы на смену ключа) шифруются сквозным шифрованием. Сервер — это **тупой ретранслятор**, который хранит и пересылает зашифрованные данные, не имея возможности их прочитать.

### 3. LRP (Lottery Ratchet Protocol)

Вместо одного сессионного ключа DuoNet генерирует **пул из 16 ключей** из исходного сессионного ключа. Каждое сообщение случайно выбирает один ключ из пула. Это значительно усложняет анализ трафика, поскольку пакеты выглядят по-разному даже в рамках одного диалога.

### 4. Клиент-клиентская ротация ключей (V4)

Ротация ключей использует **ECDH (X25519)** и выполняется **полностью между клиентами**. Сервер не участвует — запросы и ответы на ротацию — это просто зашифрованные сообщения, как и любые другие. Сервер даже не может обнаружить, что происходит ротация.

### 5. Прокси-сервис как встроенная экономика

Пользователи могут запустить прокси-сервер на своём домашнем компьютере и приглашать других использовать его. Различные уровни доступа (`basic`, `standard`, `privileged`) с дневными лимитами трафика. Это создаёт децентрализованную экономику, основанную на доверии.

```bash

Лабораторная по шифрованию: Измените examples/basic_encryption.py, добавьте своё сообщение, расшифруйте его.

Обнаружение Man-in-the-Middle: Попробуйте перехватить сообщение и посмотрите, почему верификация не проходит.

Анализ ротации ключей: Отслеживайте WebSocket трафик во время ротации — наблюдайте, что сервер видит только зашифрованные данные.

Анализ прокси-трафика: Запустите прокси-сервер и проанализируйте логи трафика (с разрешения).

Пример кода
Смотрите директорию /examples с готовыми примерами:

python
# examples/basic_encryption.py
from src.client.crypto.aes import generate_session_key, encrypt, decrypt

# У Алисы и Боба общий сессионный ключ (в реальной жизни — по защищённому каналу)
session_key = generate_session_key()

# Алиса шифрует сообщение
plaintext = "Привет, Боб! Это секрет."
ciphertext = encrypt(plaintext, session_key)

# Боб расшифровывает
decrypted = decrypt(ciphertext, session_key)
print(f"Расшифровано: {decrypted}")  # "Привет, Боб! Это секрет."
